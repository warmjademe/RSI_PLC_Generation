## 与旧版本的区别

旧版本从历史训练包一次性建立成功程序库和成功轨迹中的修复记录，测试阶段只检索。这属于静态经验复用，本身不能证明多轮 RSI。新实现增加以下闭环：

1. 从历史训练数据建立初始资产版本。
2. 用当前已准入版本完成一批训练练习任务，每题最多生成五个候选。
3. 保留所有成功、失败和不确定的生成、工具输出及 token 记录；只有通过完整验证的练习程序可以形成新增资产。
4. 从至少两个训练任务的成功程序中提炼条件化技能。技能写明适用情形、前置条件、操作步骤、验证方式和不适用边界，并保存模型调用及来源哈希。模型总结不是正确性证明。
5. 形成不可变候选版本，在固定的训练内部开发任务上与父版本比较。
6. 通过准入规则后发布；未通过则保存拒绝证据并继续使用父版本。后续练习实际消费已发布的版本。

这种实现借鉴了 [Reflexion 的语言反馈记忆](https://arxiv.org/abs/2303.11366)、[Voyager 的可持续扩充技能库](https://openreview.net/pdf?id=ehfRiF0R3a) 和 [ACE 的上下文资产更新](https://arxiv.org/abs/2510.04618)。PLC 的具体差异在于固定接口、按扫描周期定义的行为、工具验证准入，以及可追踪的跨任务训练来源。本实现不是上述方法的原论文复现，也不把程序经验复用自动等同于权重层面的自我改进。

## 训练与测试的边界

当前协议由 `rsi_protocol.make_protocol` 在看到新测试结果之前固定：

| 用途 | 数据 | 允许进入资产吗 |
|---|---|---|
| 历史经验源 | 原始 1000 个 TR 训练任务中的 970 个任务 | 允许，使用已有成功程序及绑定轨迹 |
| 多轮练习 | 三个互不重叠的训练组，每组 20 题 | 只有完整验证通过的新增程序及其有证据的修复可以入库 |
| 版本准入 | 从上述 1000 题预留的 30 个训练内部开发任务 | 开发反馈和生成轨迹不能入库；只供准入比较 |
| 最终评估 | 现有 50 个 TE 测试任务，仅 ST | 不能入库、不能选择参数、不能决定版本晋级 |

分组同时考虑 `contamination_group_id` 和 `semantic_signature` 的连通分量，整组分配，不能将相关任务拆到练习和开发两侧。练习组在生成时从检索资产中排除整个组，也排除以该组为证据的技能。分区、模型设置、预算、验证规则和晋级阈值写入协议锁定文件。

用户要求直接使用原来的 50 题测试，因此没有另建测试集。该集合曾用于设计反馈，论文不得称其为全新、未接触过的独立留出集。本轮的要求是严格禁止新的测试反馈回流。

单个测试任务仍可在五个候选的总预算内使用该题的即时编译和反馈测试诊断来修复当前程序。这是固定评测流程中的单题交互；任务结束后不能将其记忆提供给下一题或 RSI 学习器。完整判卷结果不再触发额外生成。

所有训练与晋级完成后，为保持最终比较的历史来源覆盖一致，将 30 个开发任务原本就存在的历史成功程序和旧轨迹恢复到两个最终评测资产中。只恢复训练包原始记录，绝不恢复本轮开发生成轨迹或开发反馈。于是两个最终版本都覆盖原有 1000 个训练任务；该恢复不参与参数搜索或版本选择。

## 资产内容与 token 控制

程序检索首先寻找能够覆盖当前 A、B 子系统需求条款的成功案例，并列出需求、假设及接口差异。候选策略保留完整可执行 ST 和差异说明，省去重复的源需求全文及源接口全文；展示案例时可移除普通注释，同时保留所有可执行词法内容、字符串、词法边界及换行。遇到未知编译指令或未闭合词法结构时保留原程序。展示代码和原始成功代码分别记录哈希。当前任务的完整需求和固定接口始终保留，程序不会因为上下文限制被截成不完整片段。

新程序记录实际检索过的全部来源，技能同时继承所参考旧技能的来源。练习排除规则沿这些依赖传递，不能通过新技能或新程序间接重新引入已排除的任务。长来源清单仅在提示词中显示带总数和完整绑定哈希的节选，资产文件仍保留完整来源。

修复记忆在出现确切失败后才检索。`feedback.py` 读取验证器嵌套的 `evidence.tool_report.failed_gates`；`repair_memory.py` 将历史前后程序转换为受字符预算限制的实际 diff 片段，保留来源、前后哈希及删节标记。原始完整程序仍在不可变资产及历史轨迹中。修复片段是参考，不能直接视为当前任务的正确补丁。

技能每条正文最多 1000 个字符，至少绑定两个不同训练任务；每轮最多提炼六条，每条最多三次模型调用。测试时最多检索三条技能。模型未按结构返回、内容超长或缺少来源时，保留失败调用且不创建技能，不以成功占位符代替失败。

默认上下文总预算为 24000 字符，程序预算为 14000 字符，修复预算为 6000 字符。实际 token 仍以 API 返回的 input/output usage 为准。不能将字符数下降直接当作 token 下降，也不能只报告测试 token 而忽略训练和技能提炼成本。

## 验证和版本准入

生成反馈沿用固定接口检查、MatIEC 编译及预先编写的反馈扫描用例。最终程序另外接受全部预先编写的扫描用例和列出的原生形式属性检查。验证器首先要求每个被使用的训练任务的参考程序通过，并能拒绝已有负例。

新的程序资产必须绑定实际练习结果、代码哈希和三个最终阶段的通过记录。新的修复资产还必须绑定先前候选的失败记录和前后代码。开发结果通过读取实际生成、判卷与绑定文件重建；模型自行报告的分数不能用来晋级。

当前晋级规则要求开发任务完整、模型/预算/评价条件一致、父版本原来成功的题不能丢失、不确定结果不能增加，并满足以下一项：

- 成功题数增加，同时总 token 不增加。
- 成功题数相同，同时总 token 至少下降 8%。

含有估算而非 API 实报 token 的比较不能据此宣称成本改善或晋级。这个门禁是确定的工程选择规则，不是统计显著性检验。正式论文仍需重复运行、配对差异、不确定性和外部效度分析。

版本目录包含内容哈希、父版本、配置、来源清单和适配器清单；写完并封存后原子发布。晋级和拒绝决定保留完整证据。`VersionStore.rollback` 支持显式回到以前准入的版本，并保留回滚原因及事件链。中断恢复不能清空模型计数或重置五候选预算。

## 消融接口

以下组件能够独立关闭，关闭后仍保留相同模型、候选预算及判卷规则：

| 开关或运行方式 | 检验的问题 |
|---|---|
| `use_code_memory=false` | 成功程序案例是否有帮助 |
| `use_requirement_coverage=false` | 按条款覆盖选择案例是否优于仅词法相关度 |
| `use_contract_delta=false` | 明示迁移差异是否有帮助；选择案例时仍按完整差异成本计算 |
| `use_repair_memory=false` | 历史修复经验是否有帮助 |
| `use_failure_stage_filter=false` | 按实际失败阶段筛选修复经验是否有帮助 |
| `repair_representation=full` | 紧凑修改片段是否比完整前后代码更有效 |
| `remove_donor_comments=false` | 案例中的普通注释是否值得其 token 成本 |
| `use_skill_memory=false` | 条件化技能是否带来额外收益 |
| 固定初始版本，不执行更新 | 多轮更新是否优于修正后的静态资产复用 |

关闭准入门禁的研究应单独建立明确标为探索性、不能部署的实验版本；当前生产发布接口不会接受伪造的“通过”标志。现有开关支持后续消融，但不代表所有消融已经执行或已经证明组件有效。
